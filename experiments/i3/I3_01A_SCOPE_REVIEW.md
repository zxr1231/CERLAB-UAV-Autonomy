# I3-01A 两阶段路线细化：范围审核与实施合同

日期：2026-10-12。结论：**有条件采用两阶段范围，放行最小离线可行性检查；不放行
核心观测引导或在线部署。** 本次完成定义/代码接口审核和I3-01B预注册，没有新实验结果。

## 1. 研究对象与范围变化

论文拟研究：在HIRE-style增量PRM已选定目标的条件下，依据基准路线遗漏的可达观测
机会构造少量预算受限的路线，并保留其观测价值到简化与执行层。

旧候选定义：对全部预筛选Goal参考及其变体进行精确camera排序。
新候选定义：共同阶段A先确定一个Goal和基准路线，阶段B只比较到这个**同一Goal**的
有限路线。它缩小了camera决策范围，没有解决被节点收益预筛选排除的Goal，也不保证
跨Goal全局最优。不能把缩小范围叫作旧500ms门槛通过或原失败已解决。

采取两阶段本身不作为创新。主要贡献仍须有非平凡的“基准路线遗漏观测机会→候选
构造→观测保留→真实新增观测”机制，且应超过普通多路线和朴素边际收益插点。
此前新颖性审查的风险继续有效，本次没有重判论文创新性或新增性能主张。

## 2. 阶段A：必须准确命名共同目标选择器

共同内部控制使用 **repaired distance_single + Legacy节点路径收益/估计时间**：

- Frontier引导增量PRM、节点收益预筛选、可达性逻辑继续采用既有实现。
- `routeControls.cpp` 固定起始pose/map，在图上产生单距离参考，进行几何shortcut。
- `dep.cpp::findBestPath` 仍累加中间节点和Goal的2m Legacy收益，写回旧收益缓存，
  按原运动时间评分选择 `(g*, tau0)`。
- 新地图安全复查接受后才具有有效参考；adapter失败、recovery/fallback、无有效路线
  不进入细化，保持原流程并明确记录原因。

这不是逐位不变的 `historical_legacy`：后者使用原PRM A*及相应实时读取行为，
前者是已实现的距离参考/固定快照控制。历史模式仍是独立整体基线，避免把A*和Dijkstra
差异归因于观测引导。此处“Legacy”指收益/目标选择准则，不是算法命名替换。

返航判断仍由 `dynamicExploration::exploreReplan` 的现有CompletionGate、reachableGain
检查、传感器新鲜度及阈值500决定。阶段B只能在阶段A之后、确认继续EXPLORING时调用；
RETURNING_HOME、CONFIRMING_COMPLETE、传感器/路线阻塞时跳过。camera收益不得覆盖
Legacy `bestPathGain`、节点收益缓存、完成状态或原DEP随机采样流。

## 3. 阶段B：同Goal、同完整路线评价与有限细化

输入为阶段A保留的固定pose、不可变地图、图、`g*`、tau0/raw-tau0、终点yaw和运动配置。
tau0永远是必选参考，不因新方法选择另一个Goal，不替换为比较中更有利的基准路线。
所有相互比较路线使用同一个版本化camera模型和同一地图；不同候选的历史集合独立。

首个最小版本固定 **2条最终候选：tau0 + 1条不同替代路线**。单路线控制明确只有1条，
不能参与“相同候选数下不同生成机制”的H3比较。多路线的参考/K/多样/引导采用同一
raw池上限6、额外长度/时间比例1.25及额外yaw≤pi/2；raw和最终路线都检查运动边界。
完整路线不截成短horizon，不减少物理FoV/range或0.25m/0.1rad采样密度。

新候选总数2是新范围下的初始实验合同，不是原I2每Goal最多3/全局30配置被悄悄改写。
本轮不注册3候选实测；增加候选数须新协议，避免看到结果后任意切换。

可见集合V(tau)依赖固定地图和完整姿态序列，G=|V|，U=G/T；T使用既有速度、角速度和
转向惩罚。选择U严格优于tau0的完整替代路线，绝对比较容差1e-9，平局保留tau0。
T0或参考长度≤1e-6则跳过细化。记录新增集合、丢失集合与Delta G，不能把新增集合的
大小当作净增益。只报告预测效率；实际效果必须用执行轨迹的sensor-new验证。

机会构造需要参照 `V(anchor_pose) minus V(tau0)`；anchor的奖励朝向必须出现在实际
候选采样序列中，不能用不存在的最佳朝向收益。具体anchor构造由I3-02定义；via point
加两次A*或单个Delta gain/Delta length公式不足以自动形成主要贡献。历史依赖收益
不作为普通可加负边权注入A*。

## 4. 对照、候选数量与简化

| 对照 | 用途 |
|---|---|
| historical_legacy | 原运行框架整体基线，独立保留 |
| common_A_only | 相同修复后distance_single/Legacy选择，无camera细化，辨别框架差异 |
| camera_reference_only | 同A、同Goal，评价tau0后仍执行tau0，测评价/等待开销 |
| generic_same_goal | 同A/Goal，现有Yen池中的一个不同距离变体，2条最终候选 |
| diverse_same_goal | 同池、同约束，用现有几何多样选择一个不同变体，2条最终候选 |
| opportunity_same_goal | 同A/Goal/预算，以遗漏观测机会生成变体，尚未实现 |
| naive_marginal_insertion | 未来主要主张的简单插点对照，I3-02设计时同步明确 |

生成上限相同不等于实际候选数相同。没有不同路线、shortcut后重合或超时都不能填充
副本：记录SUPPLY_DEFICIT/BUDGET_FALLBACK并回退tau0，保留在整体试验分母中。
严格H3分析必须明确各方法实际完整评分均为2；其他场合只能报告预算受限系统表现，
不能称为已排除候选数量混杂。闭环中的Goal轨迹可以随地图分化；“同Goal”严格匹配在
共同固定状态分析中成立，闭环只保证同一选择规则，不能声称所有运行Goal相同。

首次预算/供给检查使用原几何shortcut。I3-04引入观测保留后，K/多样/引导必须使用
相同版本的简化器再比较生成机制，另做几何/观测保留消融。所有shortcut试评和anchor
可见性查询计入预算及评价次数；最终2候选不能掩盖大量隐藏试评。若原shortcut使供给
消失，记录机制缺口，不将只有tau0的快结果判为多路线通过。

## 5. 预算与状态机

阶段B共同总预算 **500ms wall/steady clock**，从进入细化开始计入上下文准备、必要
快照复制、模型构造、tau0评价、anchor查询、图搜索、采样、shortcut/试评、替代路线
评价及最终安全检查。阶段A和局部B-spline另计，并报告端到端总延迟。
这比此前仅copy+camera评分的500ms范围更完整，仍不是整个规划器500ms保证。

- 额外生成过程上限50ms，嵌套在500ms内，含anchor查询/连接/几何处理；不赠送额外
  50ms。原I2的50ms定义是历史合同，不声称两者完全同一统计口径。
- 预留末尾25ms给提交前安全/新鲜度检查；可选构造/评分截止于Bstart+475ms。
  25ms是初始工程预留，不是已经证实的最坏耗时。实际超出全部计入B总时间。
- 原位地图版本/起始位姿固定；提交前验证新地图上的路线和当前位姿到首个剩余航点的
  连接。精化候选允许起点漂移≤0.25m、yaw漂移≤0.1rad（初始保守合同，待在线检查）。
  不满足则拒绝精化；不能把阈值当作物理观测集合完全不变的证明。
- 不完整参考或替代路线没有部分收益。目标2候选未完整形成/评价则回退tau0；不能把
  部分多Goal/部分路线结果充当完整比较。tau0回退也必须重新通过安全/传感器检查，
  否则保持安全的既有行为或请求重规划，不能执行过期路径。
- 合作式检查允许测量超出，但正式成本门槛500ms不增加。超出/清理时间全部记录；
  >25ms超出触发工程检查，不能靠排除清理时间获得通过。
- 若参考耗尽预算，直接回退，不跨规划轮带着旧快照继续算；没有改大预算或补跑seed。

计划模式名只是文档标识，尚不是可用ROS参数。阶段A日志和最终B路线必须分开，
全局sequence关联最终提交路线与input/B-spline/odom；否则原global路径日志会错误地
仍指向tau0。记录模型版本、Goal/路径IDs、各阶段/各类查询成本、期望/生成/去重/
完整评分数量、拒绝原因、snapshot age、位姿漂移及最终验证地图版本。

## 6. 本次审核结论与下一步

放行 I3-01B 的**一次有界离线参考+普通/几何替代路线供给和预算检查**，见配套协议。
不放行opportunity生成、信息保留shortcut或新在线仿真。只有共同框架和真实替代路线
足够、按完整B口径满足预算，才继续定义/实现I3-02的机会机制；它届时仍须自己通过
同一生成/计算预算，不能继承K路线的通过结论。

如果预算通过但供给不足：INCONCLUSIVE，不以快的单路线回退宣称多路线可行；
如果供给足够而预算失败：保留NO-GO，结束该批。再决定另行登记精确加速或收缩方法，
不进行无界校准。通过该最小检查同样不是H3实际观测/探索效率已被证明。
